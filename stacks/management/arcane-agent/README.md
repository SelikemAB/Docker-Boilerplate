# Arcane Agent

Remote Docker host agent for an [Arcane](../arcane/) manager. It supports edge mode (outbound,
the default) and direct mode (inbound).

> **Warning: the agent is equivalent to root on this host.** Anyone who controls the Arcane manager,
> or holds this agent's token, can run privileged containers here. Protect the manager with SSO and
> `internal-only@file`, keep the token secret, and revoke it in Arcane when the host is retired.

| | |
|---|---|
| Image | `ghcr.io/getarcaneapp/agent:v2.13.1` |
| Helper | `docker.io/tecnativa/docker-socket-proxy:v0.5.0` |
| Exposed | Nothing in edge mode. 3553/tcp on `BIND_ADDRESS` in direct mode |

## Quick start

1. In Arcane, go to **Environments > Add environment** and create an edge environment. Copy the
   agent token.
2. On the remote host:

```bash
cp .env.example .env && vi .env                 # set ARCANE_MANAGER_API_URL
mkdir -p secrets && chmod 700 secrets
printf '%s' 'arc_XXXXXXXX...' > secrets/arcane_agent_token   # token generated by Arcane
chmod 444 secrets/*                             # readable by the non-root container user; dir stays 700
docker compose up -d
```

### Direct mode (inbound)

In direct mode the manager connects to the agent on TCP 3553. Set `BIND_ADDRESS` to the host's
management-interface IP, firewall the port so only the manager can reach it, and prefer HTTPS
between manager and agent. Otherwise the token travels in clear text.

```bash
docker compose -f compose.yaml -f compose.direct.yaml up -d
```

## Security notes

- **Edge mode is the default.** The agent only dials out to the manager, so the host has no open
  port.
- The agent never sees the raw Docker socket. It uses `DOCKER_HOST=tcp://socket-proxy:2375`, a
  filtered proxy on an `internal` network. Swarm, secrets, plugins, configs, commit and `/auth` are
  blocked.
- **Exception (docker socket):** the proxy allows `POST`/`DELETE`, which remote management needs.
  That is enough to create privileged containers, so the agent is still root-equivalent.
- Runs as UID 65532 with all capabilities dropped and a read-only root filesystem. `/tmp` is a
  tmpfs.
- The agent token is a Docker secret, read through `AGENT_TOKEN_FILE`.
- The agent sits on its own `egress` bridge network for the outbound connection. It is not attached
  to the shared `proxy` network.
- In direct mode the port binds to `BIND_ADDRESS`, which is loopback unless you change it. No
  port-exposure exception is taken.

## Backup

The `arcane-agent-data` volume holds the agent's local state and projects. Losing it only means
re-registering the agent. Keep the token in your secret manager, or generate a new one in Arcane.
